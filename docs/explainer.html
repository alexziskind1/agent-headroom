How much agentic work can this machine hold?

Token speed cannot tell a 128 GB box from a 192 GB box. Agents can: long contexts, many sessions, tools on the CPU, several models kept warm. Five tests, five separate answers, every number from a real run.

Part 0 · pipeline

Five stages, one command each

Probe the machine, read the catalog, plan a workload that fits, run it, report. Nothing downloads or launches before run.

First we look at the computer and count its memory. Then we open a list of AI brains with how big each one is. We pick the biggest brains that fit, like packing a suitcase. Then we actually run them and time everything. Then we write down what happened in a table. Packing (the plan) is just math on two small files, so it never downloads anything. Give it a probe file from another computer and it tells you what that computer would run before you buy it.

Part 1 · probe

Where the memory actually is

Two pools or one. The probe asks the device, never compares sizes, and the planner leaves room for the OS and the tools.

Some computers have two memory boxes: one glued to the graphics card and one for everything else. Others have one big box that both share. We find out which kind by asking the chip directly, not by guessing from the sizes, because a 96 GB card next to 92 GB of normal memory looks like one box and isn't. We also always leave some space empty so the computer can breathe and run its tools.

Part 2 · planner

Cost a model, then grow the context

Weights plus KV cache plus activations plus overhead, largest model first. The first that fits gets its context grown until the budget is full.

An AI model needs room for three things: its brain (the weights), its memory of the conversation so far (the KV cache), and some scratch paper. We add those up for each model. We try the biggest brain first. If it doesn't fit, we try the next smaller one. When one fits, we keep making its conversation memory longer and longer until the box is full. That's how we find the biggest thing the computer can really do.

Agent Headroom · Crowdconcurrency headroomtest 3 · host_pressure

Add agents until the machine gives

1, 2, 4, 8, 16 agents against one server, each with a 65K KV slot on the GPU and real tool containers on the host. The last clean level is the answer.

Now we ask the computer to help 1 person, then 2, then 4, then 8 people all at once. Every extra person needs memory on the graphics card for their conversation and extra room on the normal side for their tools. We keep adding people until it gets slow or falls over. A fast graphics card with a weak 'everything else' side gets stuck early. That's how we see what normal memory and CPU are worth.

Agent Headroom · Tenantsmodel headroomtest 4 · residency

Keep four models warm. Or don't.

Four models loaded together, tasks cycling across them. A model that does not fit is evicted and reloaded, never substituted, so the swap cost is measured.

Imagine four toys you play with one after another. If your toy box fits all four, you grab the next one instantly. If it only fits three, every time you want the fourth toy you have to put one away and dig the other out of the closet. That digging takes 79 seconds here. The computer with the bigger box wins the day even though both play with each toy at exactly the same speed.

Agent Headroom · Recallcontext headroomtest 5 · warm_contexts

How many agents can RAM keep in mind?

Eight GPU slots, a fleet of n agents sharing them. Between turns an agent's whole context parks in host RAM. Past the point where RAM is full, every extra agent re-reads its context from scratch each turn.

Imagine a teacher helping a whole class, one student at a time. The teacher can only hold a few students' homework on the desk (the GPU). Everyone else's homework waits on a shelf (the RAM). If the shelf is big enough, picking up the next student's work is instant. If it is too small, the teacher has to re-read that student's whole notebook from the start every single time. More shelf, more students, same teacher.

Agent Headroom · Bridgecoherent memoryDGX Station GB300, measured

Two memories the GPU can both read

HBM on the GPU, LPDDR on the CPU, one address space over NVLink-C2C. KV and activations stay in HBM, weights fill the rest and spill into the host tier.

Some new machines have two kinds of memory: a small super-fast one glued to the chip, and a big slower one sitting next to it. The chip can read both directly. We put the parts the model touches on every single word into the fast memory, and let the rest of the model overflow into the big one. We measure how fast each memory is, so we can predict the slowdown before we run anything.

Agent Headroom · Fleetclusters

Several machines, one benchmark

The cluster probe measures every node and every link. Models go whole onto one node each, or one model is sliced across nodes and every token crosses the wire.

When one computer is too small, we chain a few together with a cable. First we measure how fast that cable is. Then there are two ways to use the team: give each computer its own whole model, so nothing crosses the cable while they work, or cut one giant model into slices across all of them, so every single word has to cross the cable. The benchmark tells you which one you got and what the cable cost you.

What is different

Five answers, no composite score

Speed benchmarks measure one model at fixed settings. Agent evals score the model, which is the same on any box that runs it. Agent Headroom starts from the machine's memory and reports where it runs out.

Other tests ask 'how fast?' or 'how smart is the AI?'. Ours asks 'how much can this computer hold, and what happens when it's full?'. It gives five separate answers: what fits, how fast, how many helpers at once, how many models stay loaded, how many helpers' memories stay warm. We don't mush them into one score, because the whole point is to see where they differ.
